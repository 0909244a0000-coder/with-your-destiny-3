# 不満点の改善 第1回：重要な戦利品を失う不安

## 対象と根拠
- 指定されたClaudeブランチ `claude/elegant-planck-znul52-skillfx` の最新 `fec4830` を確認。mainは対象外。
- 直近の未マージPR #101（`b9d41a1`）を基に修正。今回のPRにもその変更が含まれる。ユーザーがマージする。
- `src/inventory.js`：取得フィルターはノーマルのソケット2つ以上を残すが、満杯時の入れ替え保護に土台・保存ビルド用・鍛造済みがなかった。
- `src/world.js`：満杯時のノーマル／マジック素材化は土台を区別せず、地面の保護はユニーク／セットだけだった。
- `src/save.js`：地面の装備はセーブ対象外。再読み込みをまたいだ保護になっていなかった。

## 修正
- 自動分解・入れ替え・満杯時の処理・エリア移動で共通の保護理由を使う。土台保護はフィルターのON/OFFを尊重。
- 保存ビルド用と鍛造済みも自動で失わない。空の土台は自動装備で交換可（外した土台は鞄へ戻り、素材にはしない）。
- 持ち物60枠・倉庫30枠が満杯なら重要品を未受取として保存。持ち物の回収ボタンから空き枠へ受け取る。未受取は一括分解の対象外。
- 保存直前の地面の重要品も記録し、復元時に所有済み／重複IDを除外。旧セーブへ空配列を補う。職業別セーブ・バックアップ書き出し・ページ非表示／離脱でも保存。
- 未受取が60件以上なら戦闘停止。受取後に60件未満になると再開。同じ更新で同時に落ちた装備は60件を超えても消さない。
- `data/items.js`：`pendingLootLimit` 未定義 → `60` を追加（戦利品を無制限に蓄積せず保存を守る停止条件）。装備性能・敵・価格・ドロップ確率は変更なし。
- 自動保護の理由と、手動分解は可能なことを装備の説明に表示。「全て捨てる」は以前の指定どおり未ロック品を確認後に分解し、ビルド用／土台を含む件数も注意する。

## 残る不満点：次の順番
1. **整理の負担**：重複ユニーク／セットと土台の用途指定、保管する土台の候補を絞る。今回の保護で満杯までの時間が短くなる可能性も測る。1時間周回の整理回数・装備更新数・未受取数を測定してから判断。
2. **狙う目的が不明**：狙っている装備、エリア、足りないルーンをつなげて案内。ルーンワードの役割、OFFスキル熟練、セット完成の変化を画面で説明。点数は相性まで含む強さの保証ではないと明示。
3. **強化の失敗が怖い**：つけ直しの旧／新選択、鍛造の消費範囲・対象能力・残り余地の事前表示。コスト・救済の設計を整理し、無料の無限試行にしない。
4. **ビルドの選択理由が薄い**：セット／ユニーク／ルーンワードで、安全な放置・集団処理・ボス戦の比較。同条件で測るまでは強さの順位を断定しない。ユーザー指定どおり、現段階でルーンワードの数値は調整しない。
5. **終盤の目的が重なる**：エリア周回・地図・試練・双王の役割と報酬を区別。最高記録で双王まで自動的に難しくなること、日替わりの連続成功報酬が義務感を生まないか検討。
6. **戦闘結果の理解**：倒れた理由・防御不足・スキル別の働きを説明。演出の追加は判読性・重さを測りながら行う。
