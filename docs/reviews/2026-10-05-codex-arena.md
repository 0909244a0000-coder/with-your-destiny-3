# バトルアリーナ実装・検証（Codex、2026-10-05）

## 追加した遊び
- 「やり込み → バトルアリーナ」：育成済みの自分の職業を選ぶ1対1と、2〜7陣営のバトルロワイヤル。職業ごとに1人。本人の死亡で陣営脱落、最後の生存者が勝利。
- 実際の保存構成を独立した戦闘フレームにコピー。現在の職業は今の状態、他職業は最後の保存。通常戦闘の装備/型/熟練/修練/星座/箱/宝石/傭兵・召喚・変身・罠・爆弾を使用。全快開始、対戦専用の均等化なし。
- 観戦×1/2/4、停止/再開、中止。順位と通常攻撃/技/効果/傭兵別のダメージ・実測会心・命中・発動回数、被ダメージ・本人の回復を表示。冒険は観戦中停止、試合の報酬/消費/育成進行なし。

## 条件・結果
実ユーザーのセーブを読み取った測定ではなく、検証ブラウザに作ったLv40/スキルLv6の保存データを使用。装備は通常の生成処理で作り、ルーンワード・ユニーク・箱・星座・ボード・伝説の宝石・傭兵を含めた。職業順位や完成ビルドの強さを評価する試験ではない。

- 1対1：7職業の全21組×2回、42試合が決着/時間切れ処理まで完走。育成構成のコピー一致、全快開始、HP/与被ダメージが有限、陣営全体の総与ダメージ＝総被ダメージを確認。
- 7陣営戦：全63スキル×3型＝189条件。各スキルを単独ONにして発動/常時効果を確認後、30秒ずつ動作確認。防御/回復技の条件を満たすためHP35%から開始し、検証用HP装備を使って途中脱落を防いだ。強化されたテスト装備はゲームのdata/へ入れていない。
- 味方攻撃なし、反射、反射の再帰なし、弾無効時に吸血/拘束なし、拘束で本人の移動/通常攻撃が停止、死後回復なし、停止で時計不変、180秒タイの同率順位、コピーのStorage分離、読み込み中止→再開、閉じた後のiframe除去が成功。
- 観戦前後で原キャラのstate/HPと全職業の保存内容が一致（テスト中は通常の定期保存だけ停止）。実ゲームは本編の保存を続けるので保存時刻は更新されるが、対戦から育成内容は変えない。
- 1440px/390pxで確認。横はみ出し0、操作ボタン48px以上、キャラのポーズ計算はNaNなし、エラー0。開戦後の選択折りたたみ、縦スクロール、結果の技別内訳、閉じるを確認。
- HTTP同一オリジンでも、ブラウザのWebセキュリティを無効にせず、実UIから1対1→停止→7陣営戦→終了を確認。画像のownerDocumentが親画面であることを確認し、画像キャッシュで破棄済みフレームを保持しない構成にした。
- 7職業のfuzz：各1500操作、各50再読み込み、NaNなし/エラー0。combo：7職業×季節×通常/ボス/試練/日替わり/地図/双王、エラー0。
- 拠点・通常リザルト・戦利品保護・冥爆術師の既存検証も成功。冥爆術師は専用22項目/15画像/84組×3型＝252条件が成功。

## 重要な仕様・限界
1. 保存領域への対戦の書き込みを避けるため、iframeは最初からメモリStorageを使う。main/UI/オフライン進行を起動せず、経験値/戦利品/挑戦進行を伴う敵死亡処理は対戦用に差し替える。終了で元の装備/ポイント/冒険HP/停止状態へ戻る。
2. 一時的な祠/変身/バフは持ち込まず試合内で再発動。通常キャラは精鋭やボスではないため、精鋭/ボス限定能力は発動しない。召喚/設置物は本人の脱落時に除去。反射同士の無限連鎖と死後回復を防ぐ。
3. 180秒で生存者は同率1位。同じ刻み（0.05秒）で脱落した陣営も同順位。処理順は開始時に無作為化し、先頭を毎刻み交代する。レベル/装備差を残すのはユーザーの方針。
4. 同じ職業の別ビルド2人、他プレイヤー/端末とのオンライン対戦、報酬/ランキング保存は未実装。未育成や読めない保存は選択できない。
5. 本物のiPhoneでのFPS/メモリ、全装備能力の全組み合わせ、育成済み最終ビルドの勝率は未測定。7人の演出は描画だけを上限で抑える（ダメージ判定/召喚数/技の性能を減らさない）。
