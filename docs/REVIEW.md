# ほかのAI（ChatGPT・Codex など）に確認と相談を頼むときの手順

コードは直さず、**動かして測った結果と、改善の提案だけ**をもらうための手順です。
直すのは提案を読んだあと、別の作業で行います（ルールは `AGENTS.md`）。

## 1. 準備（1回だけ）
```
npm i playwright
npx playwright install chromium
```
ビルドは不要。`index.html` をブラウザで開けばゲームが動きます。

## 2. 測る道具（`tools/`）
| 道具 | 何がわかるか | 例 |
|---|---|---|
| `balance-sim.js` | 新しいセーブから自動で遊ばせ、ボスを倒した時間・倒れた回数・何に倒されたか（deathCauses）・試練の段階を出す | `node tools/balance-sim.js 40 paladin 15` |
| `fuzz-test.js` | ボタンをでたらめに押し続け、エラーと壊れた数値を探す | `node tools/fuzz-test.js druid 1500` |
| `combo-test.js` | 職業 × 季節 × 遊び方の組み合わせを動かし、エラーを探す | `node tools/combo-test.js` |

- `balance-sim.js` の引数：`[分数] [職業] [試練の分数] [スキル3つ(カンマ区切り、- で省略)] [傭兵(- で省略)] [育て方]`
- 育て方：`game`（省略時）はゲームの「スキルを自動で上げる」と「自動装備」をそのまま使う。`sim` は前からの測り方（data の先頭3スキル・道具の点数で装備）
- `deathCauses` は「エリア:とどめを刺した敵と攻撃の種類」（例：`inferno:業火の溶岩の巨人の攻撃`）
- 職業：`barbarian` `sorceress` `necromancer` `paladin` `assassin` `druid`
- 傭兵：`spear` `archer` `mage`
- 1回に数分かかります。結果は運でぶれるので、**同じ条件で2〜3回**測ってください。

## 3. 今の目安（ここから大きくずれていたら知らせてほしい）
- どの職業も、ふつうに育てると6体目のボス（業火の玉座）を **20〜25分** で倒す
- クリア後の試練（15分）は段階 **11〜13** くらい
- `fuzz-test.js`・`combo-test.js` のエラーは **0**

## 4. 見てほしいこと
1. 職業ごとの強さの差（クリア時間・倒れた回数・試練の段階）
2. 倒れる原因の偏り（特定の敵や精鋭だけが強すぎないか）
3. 序盤の遊びやすさ（最初の10分で何が起きるか、待ち時間が長すぎないか）
4. エラーや、表示がおかしい所
5. 有名なハクスラ（Diablo・Path of Exile など）と比べて、物足りない・わかりにくい所

## 5. 結果の出し方
- **コードや `data/` は変えない。** 結果は `docs/reviews/日付-名前.md`（例：`docs/reviews/2026-10-03-gpt.md`）に書いて、PR にする
- 書く内容：
  - 測った条件（コマンドそのまま）と結果の数字
  - 問題と、その根拠（どの数字からそう言えるか）
  - 提案。数値を変える提案は **`data/` のどのファイルのどの値を、いくつからいくつへ** の形で
  - 重要な順に並べる
- 日本語で、短く
